We fixed the original tutorial notebook so it runs on a 24GB GPU, then built and evaluated three alternatives on a shared 1,000-query known-item benchmark (200 recipes × title, paraphrase, Spanish, Bengali and Chinese queries). The best pipeline, now the repository's main, replaces the Nemotron VL models with Qwen3-VL-Embedding-2B and Qwen3-VL-Reranker-2B, adds BM25 fused with Reciprocal Rank Fusion only for queries whose words occur in the corpus vocabulary, reranks on recipe text, and answers with Qwen3.5-4B. It is more accurate on every query set and an order of magnitude faster than the baseline's image + text reranking.

2. Task, data and hardware

  • Dataset: mrdbourke/recipe-synthetic-images-10k, 10,096 Food.com recipes, each a rendered 1275×1650 recipe-card image plus markdown (title, description, ingredients, steps, tags, five reviews).
  • Task: retrieve the right recipe for a text query (any language), an image, or both; optionally generate an answer grounded in the top three recipes.
  • Hardware: one Google Colab NVIDIA L4 (24GB, 72W power cap), driven from the terminal with colab-persist over SSH. All final models together use 17.7GB of GPU memory, so the pipeline also fits an RTX A5000 (24GB).
  • One-off corpus embedding cost on the L4: Qwen3-VL-Embedding-2B 48.5 min (image capped at ~400 tokens + recipe text without reviews); Nemotron Embed VL 2 h 19 min (tutorial format: 6 tiles + thumbnail and full text, ~4k tokens per recipe).

4. Evaluation method

Known-item retrieval on 200 recipes sampled with seed 42 (results/eval_queries.json). For each target recipe there are five queries: its title; a 5–12 word paraphrase written by Qwen3.5-4B from the recipe without the title's words; and the paraphrase machine-translated by Qwen3.5-4B into Spanish, Bengali and Chinese. We report Recall@1/@10 and MRR@10 of the target recipe and mean latency (retrieval, rerank and any LLM planning; answer generation excluded, ~20 s with Qwen3.5-4B).

Caveats: queries are synthetic; the Bengali translations are rough (many English food words transliterated, a few mistranslations); near-duplicate recipes exist (e.g. two "banana sour cream bread" recipes) so Recall@1 under-counts; slow methods were evaluated on 50 (rerank, agent) or 25 (image + text rerank, thinking agent) queries per set, giving roughly ±7–10 points of sampling error, so differences smaller than that between slow methods are not significant.

6. Findings

6.1 The original notebook did not run, and had latent bugs

  • ValueError: Sample larger than population: image paths were globbed from a local folder that only existed on the author's machine (0 images). Fixed by sampling the dataset's image column.
  • Reranking 20 image + text pairs in one forward pass runs out of memory on a 24GB GPU (CUDA OOM at 20.4GB) → batched (4 pairs).
  • The reranker's processor kwargs were built under a misspelled name and never passed; image queries were passed to the reranker as its text question; get_top_n_scores_and_samples ignored top_n; "Run all" blocked on demo.launch(debug=True) and would have tried to publish a Space. All fixed (notebooks/multimodal_rag_tutorial_baseline.ipynb, end to end on the L4 in 138 s).

6.2 Hidden embedding-compatibility trap

The demo Space's precomputed document embeddings only reproduce with the tutorial's pinned embed commit (cosine 0.9999). Every official revision of llama-nemotron-embed-vl-1b-v2 tokenizes and masks differently (cosine ≈ 0.86, under both transformers 4.57 and 5.x), and the pinned commit cannot run on transformers 5, which Qwen3.5 requires. Re-embedding the corpus with the official revision fixed the mismatch and improved plain dense retrieval: title Recall@1 0.94 → 0.96, paraphrase 0.65 → 0.75.

6.3 The reranker revision matters more than image inputs

With the tutorial's pinned reranker commit, image + text reranking is worse than no reranking on most sets (mean Recall@1 0.400 vs 0.414) at ~15 s per query, and text-only reranking is broken (title Recall@1 0.48). The current official revision reranks recipe text well in ~0.6 s (title 0.98, paraphrase 0.86). Dropping the reviews from the reranked text halves its cost.

6.4 Hybrid search helps English and hurts other languages: gate it

BM25 over the English corpus improves English paraphrase retrieval but injects noise for other languages; with Qwen3-VL, ungated hybrid drops Spanish Recall@1 from 0.41 to 0.15. A free, language-agnostic gate fixes this: use BM25 only if ≥ 80% of the query's non-stopword tokens occur in the corpus vocabulary. On our queries this passes 100% of English, 9% of Spanish and ~0% of Bengali/Chinese queries, keeping the English gains and restoring dense-only behaviour elsewhere (Nemotron Spanish: 0.10 ungated vs 0.26 gated).

6.5 A multilingual multimodal embedding model is the biggest single lever

Qwen3-VL-Embedding-2B improves dense Recall@1 on non-English queries 1.6–3.6× versus the re-embedded Nemotron (Spanish 0.26 → 0.41, Bengali 0.17 → 0.34, Chinese 0.13 → 0.47) while matching it on English, and its reranker (with the BM25 gate) adds another 16–30 points on every non-English set.

6.6 Agentic search planning helps weak retrievers but does not win

Letting Qwen3.5-4B translate/rewrite the request via tool calls lifts the Nemotron pipeline on Bengali (dense 0.17 → agent 0.40) but hurts exact-title queries (rewriting loses the exact name), costs ~5 s per query with the reference kernels, and thinking mode adds ~10 s more with no accuracy gain. On top of the Qwen3-VL pipeline it does not improve the average (0.668 with agent vs 0.748 without), so it ships as an option (--agent) for vague or multi-part requests rather than the default.

6.7 Image + text reranking: best for English only

Reranking with the recipe-card images reaches the best English numbers (title 1.00, paraphrase 0.92) but is worse than text-only reranking for non-English queries and ~3× slower; text reranking is the default and image + text an option (--rerank-images).

6.8 Generation

Qwen3.5-4B (natively multimodal, Feb 2026) produces grounded, cited markdown answers and describes image queries for lexical search (e.g. the kitchen-bench photo → "tomato pasta with fresh basil and parmesan cheese"). Thinking is disabled for latency; an answer takes ~20 s on the L4 because causal-conv1d is not installed (flash-linear-attention is).

7. Recommendation (what is on main)

  • Default: Qwen3-VL-Embedding-2B dense + vocabulary-gated BM25 (RRF) → Qwen3-VL-Reranker-2B on recipe text → Qwen3.5-4B grounded answer.
  • Options: --rerank-images for maximum English accuracy, --agent for vague requests, --backend nemotron for the improved Nemotron stack. The fixed original tutorial is kept as notebooks/multimodal_rag_tutorial_baseline.ipynb / standalone/baseline_app.py.
  • Future work: human-labelled multi-answer relevance judgements; native-speaker queries (especially Bengali); install causal-conv1d or serve Qwen3.5 with vLLM for faster answers; Qwen3-VL-Embedding-8B on a 48GB GPU; host the 41MB corpus embeddings on the Hub.
